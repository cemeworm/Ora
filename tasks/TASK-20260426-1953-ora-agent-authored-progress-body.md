## Goal
- Implement agent-authored live progress body text for Ora chat runs. Running assistant turns should show short natural-language progress narration generated by the runtime provider from current run context, while final answers and safety/approval states remain authoritative.

## Scope / Out of scope
- In scope: runtime progress narration events, desktop config enablement, desktop view-model selection of latest progress summary, focused tests.
- Out of scope: periodic timer heartbeats, business-agent output format changes, broad UI layout changes.

## Constraints
- Compatibility: do not change shared event schema; use `task.progress` payload metadata.
- Performance: low-token narrator, key-stage only, enabled for desktop runs without disrupting generic runtime mock tests.
- Risk: extra provider calls must not pollute the main agent execution path or fail the run.
- Tool/Environment limits: dirty worktree; do not revert unrelated existing changes.

## Plan
1. `apps/runtime/src/harness/runtime-kernel.ts` - add provider-backed `emitProgressNarration` and trigger at key lifecycle points.
2. `apps/desktop/src/lib/useRunActions.ts` - enable progress narration for desktop-started streaming runs.
3. `apps/desktop/src/lib/viewModel.ts` - show latest `kind: "chat_progress"` summary for running/queued turns.
4. Runtime/desktop tests - cover event emission, view-model priority, and existing stream-delta safety.

## Decisions
- Decision: gate provider-backed narrator behind `config.metadata.progressNarration === true`, and set it from desktop run actions.
  - Why: real chat runs get natural progress, while low-level runtime tests and deterministic provider mocks are not surprised by extra provider calls unless they opt in.
  - Alternatives: default-on globally; rule-only summaries.
  - Tradeoffs: direct runtime API callers must opt in for narrator events.
